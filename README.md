# Nite — живой рекламный дашборд

Интерактивный отчёт по рекламе Meta (Facebook / Instagram) для проекта Nite.
Данные тянутся из рекламного кабинета **AD_UA** (`act_336853233618777`) через Meta
Marketing API, обновляются каждые 3 часа и публикуются на GitHub Pages за паролем.

Собран из шаблона `~/desa-dashboard` по рунбуку `docs/REPLICATE.md`. Отличие одно и
существенное: **CRM-слоя нет** — выгрузки лидов пока не существует, поэтому квал-лидов,
CPQL, статусов сделок и географии в отчёте нет вовсе (не прочерками, а физически).

## Что внутри
- KPI: расход, лиды, CPL + план/факт месяца; показы, клики, CTR, CPM, CPC.
- Динамика по дням: расход и лиды, CPL, CTR.
- Воронка показы → клики → лиды с конверсиями между шагами.
- Потоки **EN / RU** — разбивка по языку кампаний (второй токен в имени кампании).
- Кампании с дрилл-дауном: кампания → адсет → объявление.
- **Плейсменты** — расход, показы, CTR, лиды и CPL по каждому плейсменту, плюс
  переключатель на уровень площадок (Facebook / Instagram / Threads).
- **Галерея креативов** — постеры 9:16, сортировка по лидам / CPL / расходу / CTR,
  живое превью Meta в модалке.

## Стек
Vite + React + TypeScript + Tailwind v4 + Recharts. Данные — один зашифрованный файл
`public/data/latest.enc` (AES-256-GCM, ключ из пароля через PBKDF2). Сборщик — Node 18+
без внешних зависимостей.

## Локально
```bash
npm install
DASHBOARD_PASSWORD='<пароль>' npm run data
npm run dev
```

`npm run data` = `fetch-meta.mjs` → `encrypt-data.mjs`.
Токен Meta берётся из `~/.config/claude-meta/token.env` или из `META_ACCESS_TOKEN`.

## Как обновляются данные

Каждые 3 часа GitHub Actions перезапускает `scripts/fetch-meta.mjs` и деплоит результат.
Настройки — переменные окружения в `env:` блока workflow (дублируются дефолтами в шапке
скрипта, но в CI передаются явно): `META_ACCOUNT_ID`, `MIN_DATE`, `LEAD_TYPE`,
`PLAN_BUDGET`, `PLAN_LEADS`, `PLAN_CPL`, `PREVIEW_FORMAT`.

Страница показывает срез на момент последней сборки (максимум 3 часа). Нужно прямо
сейчас — кнопка **Run workflow** в Actions, ~2 минуты; на самой странице та же кнопка
появляется по `?admin`.

### Окно и лид

`MIN_DATE = 2026-05-01` — старт флайта Nite. Первый день с расходом — 12.05.2026, с него
и начинается шкала.

Лид — событие `lead`. На этом кабинете все три определения сходятся
(`lead` 476 / `offsite_conversion.fb_pixel_lead` 475 / `onsite_web_lead` 476 за весь
флайт), так что цифра совпадает с Ads Manager. Это свойство кабинета, а не константа —
при переносе на другой аккаунт проверять заново.

### Проверка целостности

Расход по плейсментам сверяется с расходом аккаунта: расхождение больше 1% валит
сборку — значит breakdown-проход недобрал строк и таблица плейсментов занизила бы расход.
Сверка печатается в лог каждого прогона.

## План

`PLAN_BUDGET $6000` и `PLAN_CPL $20` (отсюда `PLAN_LEADS 300`) трактуются как **план
месяца** — карточки KPI считают прогресс от начала текущего месяца данных, а не от начала
флайта. Если план был на весь флайт, а не на месяц, менять `PLAN_BUDGET` / `PLAN_LEADS`
в `.github/workflows/deploy.yml`.

## Деплой (GitHub Pages + авто-крон)
1. Репозиторий **`nite-dashboard`** — имя важно, под него настроен `base` в `vite.config.ts`.
2. Pages включается один раз командой (а не `enablement: true` в workflow, он падает на
   свежем репо): `gh api -X POST repos/<user>/nite-dashboard/pages -f build_type=workflow`.
3. Settings → Secrets and variables → Actions:
   - Secret `META_ACCESS_TOKEN` — системный токен Meta.
   - Secret `DASHBOARD_PASSWORD` — пароль входа в дашборд.
   - Variable `META_ACCOUNT_ID` = `act_336853233618777`.
4. `git push` → workflow соберёт и опубликует сайт, дальше пересборка каждые 3 часа.

Итоговая ссылка: `https://igoradakhovskiy-cyber.github.io/nite-dashboard/`

## Безопасность
Расшифровка происходит в браузере: неверный пароль — данные просто не расшифруются,
обойти через DevTools нечего. В репозиторий не попадают ни токен, ни `.data/latest.json`,
ни постеры — всё пересобирается в CI при каждом прогоне.

## Когда появится выгрузка CRM

`scripts/fetch-crm.mjs` лежит в репозитории целиком, но **не подключён** к workflow и без
`SHEET_ID` отказывается запускаться. Весь интерфейс уже умеет CRM-слой и включает его сам,
как только в датасете появляется блок `crm`: квал-лиды и CPQL в KPI, четвёртый шаг воронки,
колонки в потоках, кампаниях и плейсментах, статусы сделок, география, сортировка креативов
по квалам.

Чтобы включить:

1. **Проверить UTM-макросы в объявлениях** — без них джойна не будет вообще:
   `utm_source=facebook&utm_campaign={{campaign.name}}&utm_content={{ad.name}}`.
2. Открыть таблицу на чтение по ссылке, проверить `curl -s -o /dev/null -w "%{http_code}"
   "https://docs.google.com/spreadsheets/d/<ID>/gviz/tq?tqx=out:csv&sheet=<TAB>"` → 200.
3. Перенастроить `COL` и `EXPECTED_HEADER` в `scripts/fetch-crm.mjs` под реальную шапку —
   сейчас там раскладка таблицы Desa. Колонки читаются **по индексу, а не по имени**:
   в той таблице было две колонки с именем `Квалификация` с разной логикой.
   Валидацию шапки не отключать: gviz не отдаёт 404 на неверное имя вкладки, он молча
   возвращает первую.
4. Вернуть шаг `Join CRM data from Google Sheets` в `.github/workflows/deploy.yml`
   (закомментирован там же, где стоял), добавить переменную `SHEET_ID`, вернуть
   `PLAN_QUAL` / `PLAN_CPQL` и `fetch-crm.mjs` в `npm run data`.

Подробности механики — `docs/REPLICATE.md`, раздел «CRM-слой».
